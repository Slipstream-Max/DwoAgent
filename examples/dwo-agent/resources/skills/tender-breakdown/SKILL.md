# 招标文件拆解

## 目标

把招标文件拆成五个交付文档：

1. `招标分析文档`：给决策和整体理解使用。
2. `资质校验文档`：给人员逐项确认是否满足入围、资质、废标要求。
3. `价格评分文档`：给人员补充报价、限价、价格评分规则和测算依据。
4. `商务评分文档`：给人员补充商务响应材料、证明文件和得分判断。
5. `技术评分文档`：给人员补充技术响应材料、证明文件和得分判断。

默认严格产出五个文档。只有用户明确要求合并商务与技术时，才把第 4、5 个合并成一个文档。

## 工作流程

1. 若源文件是 `.docx` 或文本型 `.pdf`，优先用 `scripts/extract_tender_text.py` 抽取原文；若是扫描件，先说明需要 OCR 或人工复核。
2. 读取抽取文本或用户提供的原文，先定位目录、招标公告、投标人须知、资格要求、废标条款、评分办法、合同/服务要求、附件格式。
3. 提取招标信息汇总字段，不确定的值标记为 `未找到`，不要猜。
4. 提取入围最低标准：非黑名单要求、资质要求、废标项。
5. 拆评分标准构成：价格、商务、技术三类；逐项记录评分点、分值、评分规则、所需证明材料。
6. 识别隐含分值标记：例如星星、三角形、圆点、表格符号。若文件说明“星星=2分、三角形=1分”，按说明换算；若没有说明，标为 `需人工确认`。
7. 先输出五个 Markdown 文档，必要时用 `scripts/render_tender_docx.py` 渲染成五个 Word `.docx`。每个结论都尽量带文件页码、章节名或原文定位；找不到定位时说明来源不明。

## 配套脚本

脚本只负责文件读写和格式化，不替代招标分析判断。

### 抽取 Word/PDF 原文

使用 `scripts/extract_tender_text.py`：

```powershell
uv run python C:\Users\11307\.codex\skills\tender-breakdown\scripts\extract_tender_text.py 招标文件.docx -o extracted.txt
uv run --with pypdf --with pymupdf python C:\Users\11307\.codex\skills\tender-breakdown\scripts\extract_tender_text.py 招标文件.pdf -o extracted.txt
```

- `.docx` 抽取不需要额外依赖，并尽量保留表格为 `|` 分隔文本。
- `.pdf` 抽取依赖 `pypdf` 或 `pymupdf`，只适合文本型 PDF。
- 扫描版 PDF 若抽不到正文，先提示用户需要 OCR 或更清晰原文件。
- 输出文本使用 UTF-8 with BOM，便于 PowerShell 和中文内容读取。

### 渲染 Word 文档

先按本 skill 生成五个 Markdown 文档，再用 `scripts/render_tender_docx.py` 批量转成 `.docx`：

```powershell
uv run --with python-docx python C:\Users\11307\.codex\skills\tender-breakdown\scripts\render_tender_docx.py .\拆标输出-md -o .\拆标输出-docx
```

也可以转换单个 Markdown：

```powershell
uv run --with python-docx python C:\Users\11307\.codex\skills\tender-breakdown\scripts\render_tender_docx.py .\招标分析文档.md -o .\招标分析文档.docx
```

Markdown 中的标题、段落、列表和表格会被转为 Word 样式。若用户要求直接输出 Word，仍应先在内存或临时文件中组织成四份 Markdown 结构，再调用脚本渲染，避免 Word 写入逻辑和招标分析逻辑混在一起。

## 核心提取项

### 招标信息汇总

必须提取以下字段：

- 名称
- 编号
- 甲方/用户/招标单位
- 招标机构
- 服务费
- 报名时间、地点、费用、方式
- 投标时间、地点
- 开标时间、地点
- 招标金额 / 预算金额
- 最低投标价 / 限价（可能在评分办法中出现）
- 联系方式

### 入围最低标准

必须提取以下三类：

- 非黑名单：失信、重大违法、政府采购严重违法、关联关系、黑名单、信用中国/中国政府采购网等限制。
- 资质：营业执照、行业许可证、认证、业绩、人员、财务、社保、纳税、授权、联合体、特定资格等。
- 废标项：无效投标、否决投标、实质性不响应、逾期、未盖章签字、保证金、报价异常、文件缺失、格式错误等。

### 评分标准构成

按 `价格`、`商务`、`技术` 拆分。每个评分点记录：

- 评分类别
- 评分点名称
- 分值
- 评分规则
- 需要提交/补充的材料
- 风险或疑问
- 文件位置

若分值直接写明，直接使用。若通过符号标记分值，必须记录符号映射依据。若无法确认，写 `需人工确认`。

## 文档 1：招标分析文档

用于整体分析，不要写成材料收集表。建议结构：

```markdown
# 招标分析文档

## 1. 项目概览
| 字段 | 内容 | 文件位置 | 备注 |
|---|---|---|---|

## 2. 关键时间线
| 事项 | 时间 | 地点/方式 | 风险提醒 | 文件位置 |
|---|---|---|---|---|

## 3. 金额与报价边界
| 项目 | 内容 | 文件位置 | 备注 |
|---|---|---|---|

## 4. 入围最低标准摘要
| 类型 | 要求摘要 | 是否硬性门槛 | 文件位置 |
|---|---|---|---|

## 5. 评分构成摘要
| 类别 | 总分/分值 | 主要评分点 | 备注 |
|---|---:|---|---|

## 6. 初步风险与待确认事项
| 风险/问题 | 影响 | 建议动作 | 文件位置 |
|---|---|---|---|
```

```markdown

|---|---|---|---|---|
```

## 输出要求

- 文档使用中文。
- 用表格承载可校验信息，用短段落说明判断。
- 商务和技术不要合并输出，除非用户明确要求合并。
- 不确定时写 `未找到`、`未说明` 或 `需人工确认`，不要补造。
- 对废标项和硬性资质要求保持保守，标注为高风险。
- 若招标文件内容互相矛盾，把矛盾原文分别列出，并放入待确认事项。
- 若用户提供的是图片或扫描件，先转写可见内容；无法辨认的地方标注 `图片不清晰，需复核`。
